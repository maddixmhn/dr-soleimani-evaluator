# دکتر سلیمانی | ارزیاب مستقل دانشگاه ایجنتیک فاران

داشبورد وب و PWA فارسی برای تحلیل فایل رویدادهای نسخه‌دارِ دانشگاه ایجنتیک فاران. ورودی می‌تواند fixture ساختگی یا خروجی پالایش‌شدهٔ اجرای واقعی Paperclip باشد. اتصال Paperclip از workflow دستی n8n می‌گذرد و فایل را اپراتور در همین مرورگر بارگذاری می‌کند؛ این سایت API مستقیم، LMS یا پایگاه دادهٔ عملیاتی ندارد و نمی‌تواند نقش/دسترسی ایجنت‌ها را تغییر دهد.

## مشخصات پروژهٔ درسی

- **درس:** ارزیابی کارایی سیستم‌های کامپیوتری
- **استاد ارائه:** دکتر علی سلیمانی
- **دانشجو:** محمد مهرانی
- **مخزن:** [github.com/maddixmhn/dr-soleimani-evaluator](https://github.com/maddixmhn/dr-soleimani-evaluator)
- **نسخهٔ نمایشی وب:** [dr-soleimani-evaluator.vercel.app](https://dr-soleimani-evaluator.vercel.app)
- **سامانهٔ دانشگاه:** [فاران](https://github.com/maddixmhn/faran) · [نسخهٔ وب](https://faran-mu.vercel.app)

## این برنامه چه می‌کند؟

ارزیاب، فایل JSON رویدادهای پالایش‌شده را در مرورگر می‌خواند و شاخص‌های قطعی و چند هشدار تحلیلی می‌سازد:

- نرخ تکمیل بر اساس وضعیت‌های شناخته‌شده؛ وضعیت نامعلوم موفق فرض نمی‌شود.
- اجرای تکراری تسک و شناسهٔ رویداد تکراری.
- رویدادهای فاقد `policy_version` برای بررسی بازتولیدپذیری.
- عملکرد تفکیک‌شده بر اساس `agent_id`: تعداد اجرا، تکمیل/شکست، تکرار، زمان و هزینهٔ ثبت‌شده.
- نمودار روند روزانه و baseline خطی توصیفی، فقط با حداقل پنج بازهٔ روزانه.
- پیشنهادهای بازبینی برای وظیفه، rubric، ورودی، policy و idempotency؛ این پیشنهادها نیازمند تأیید مسئول‌اند.

در پنل می‌توان بازهٔ تاریخ، ایجنت، وضعیت و شناسهٔ تسک/رویداد را فیلتر کرد. گزارش قابل دانلود شامل خلاصهٔ JSON، خلاصهٔ CSV به تفکیک ایجنت و چاپ مرورگر برای ذخیرهٔ PDF است. دادهٔ بارگذاری‌شده در backend ذخیره نمی‌شود؛ خروجی روی همان دستگاه ساخته و دریافت می‌شود.

## محدودیت و تفسیر درست نتیجه

`core.mjs` محاسبات قطعی را انجام می‌دهد و به مدل زبانی درخواست نمی‌فرستد. نمونهٔ پیش‌بینی، پیش‌بینی مدل یا تضمین آینده نیست؛ یک extrapolation ساده از پنج نرخ مشاهده‌شده و دامنهٔ نوسان همان نمونه است. این دامنه بازهٔ اطمینان آماری نیست.

نمونهٔ نمایشی در داشبورد دادهٔ ساختگی است و شاهد عملکرد واقعی ایجنت نیست. workflow تاریخچهٔ Paperclip به‌صورت دستی در n8n اجرا می‌شود و فرادادهٔ پالایش‌شده می‌دهد؛ feed فعلی صفر اجرا دارد، پس هیچ نتیجهٔ عملکردی واقعی برای گزارش نیست. فایل export امضا نمی‌شود و اصالت آن مستقل تأیید نمی‌شود. دسترسی چندکاربره، همگام‌سازی خودکار، audit log قابل اتکا و کنترل سیاست مرکزی وجود ندارد. پیش از تصمیم آموزشی یا عملیاتی واقعی، rubric تأییدشده، حجم نمونهٔ کافی و بازبینی انسانی لازم است.

## اجرای محلی از صفر

برای اینکه Service Worker و PWA درست کار کنند، فایل‌ها را با وب‌سرور HTTP باز کنید؛ بازکردن مستقیم `file://` کافی نیست.

### روش Python

Python 3 را نصب کنید، PowerShell را در پوشهٔ پروژه باز و اجرا کنید:

```powershell
python -m http.server 8001
```

سپس `http://localhost:8001` را باز کنید. برای ساخت گزارش نمونه، «نمایش دادهٔ نمونه» را بزنید. برای تحلیل رویداد فاران، فایل JSON پالایش‌شده را بارگذاری کنید. فیلترها را اعمال کنید و یکی از خروجی‌های JSON، CSV یا چاپ/PDF را انتخاب کنید.

### اتصال دستی به Paperclip محلی

در Docker محلیِ دانشگاه، به `http://localhost:8001` بروید و «دریافت اجرای Paperclip» را بزنید. در n8n گراف `Faran → ارزیاب دکتر سلیمانی` را دستی اجرا کنید، خروجی node پایانی را به فایل JSON ذخیره و در همین صفحه بارگذاری کنید. این feed فقط run metadata را می‌خواند؛ prompt، شرح تسک، دیدگاه، provider trace، credential و دادهٔ دانشجو را صادر نمی‌کند. اگر feed خالی است، Paperclip هنوز اجرای عامل ثبت نکرده است. برای اجرای محلی این Docker profile و محدودیت‌هایش، [راهنمای اپراتوری فاران](https://github.com/maddixmhn/faran/blob/master/infra/workflow/README.md) را ببینید.

برای اجرای Docker از ریشهٔ مخزن فاران:

```powershell
docker compose --env-file infra/workflow/.env -f infra/workflow/compose.yaml -f infra/workflow/compose.local.yaml --profile dashboards up -d --build faran-web evaluator-web
```

آدرس‌ها: `http://localhost:8000` دانشگاه و `http://localhost:8001` ارزیاب. سرویس‌ها فقط روی loopback در دسترس‌اند.

### روش npm و Android

نیازمند Node.js سازگار با Capacitor 8، Android Studio، Android SDK و JDK سازگار است:

```powershell
npm ci
npm run android:sync
cd android
.\gradlew.bat assembleDebug
```

برای بازکردن پروژه در Android Studio از ریشهٔ مخزن:

```powershell
npm run android:open
```

APK آزمایشی در `android/app/build/outputs/apk/debug/` ساخته می‌شود. پوشهٔ `www/` در Git نگهداری نمی‌شود؛ هنگام sync از فایل‌های اصلی سایت کپی می‌شود. APK release و امضای آن در این مخزن آماده نشده است.

## قالب دادهٔ ورودی

برنامه یکی از دو شکل زیر را می‌پذیرد: آرایهٔ رویدادها یا شیئی با `contract` و آرایهٔ `events`.

```json
{
  "contract": "faran-event-schema/1.0",
  "generated_at": "2026-11-22T10:00:00Z",
  "synthetic": true,
  "events": [
    {
      "event_id": "evt-001",
      "schema_version": "1.0",
      "occurred_at": "2026-11-22T09:45:00Z",
      "agent_id": "lab-agent",
      "task_id": "task-001",
      "status": "completed",
      "duration_ms": 3200,
      "cost": { "amount": 0, "currency": "USD" },
      "policy_version": "mock-policy-v1",
      "evidence_refs": ["fixture:offline-baseline-v1"],
      "synthetic": true
    }
  ]
}
```

فیلدهای اصلی `event_id`, `occurred_at`, `agent_id`, `task_id`, `status` هستند. وضعیت‌های شناخته‌شده `completed`, `failed`, `blocked`, `cancelled` هستند. برای تولیدگزارش، دادهٔ شخصی/آموزشی یا اسرار دسترسی را وارد فایل نکنید؛ فقط شناسه‌های لازم و ارجاع‌های پالایش‌شده را به کار ببرید. حداکثر ۵۰٬۰۰۰ رویداد در هر فایل پذیرفته می‌شود.

## استقرار نسخهٔ وب

نسخهٔ فعلی سایت ایستا است و در Vercel قابل میزبانی است. مخزن را وارد Vercel کنید، **Other** را به‌عنوان framework انتخاب کنید، پوشهٔ ریشه را نگه دارید و خروجی استاتیک را از همان ریشه سرو کنید. build step لازم نیست. پس از استقرار، بارگذاری fixture، گزارش‌گیری، نصب PWA و پیوندهای دانشگاه را در مرورگر بررسی کنید.

مرورگر برای محاسبهٔ تحلیل کافی است؛ دادهٔ رویداد به سرور فرستاده نمی‌شود. این رفتار را با افزودن analytics، API یا storage تغییر ندهید مگر آنکه حریم خصوصی، retention و کنترل دسترسی از نو طراحی و مستند شوند.
